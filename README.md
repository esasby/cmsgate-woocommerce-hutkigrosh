# Модуль оплаты ХуткiГрош (ЕРИП) для WooCommerce

Модуль обеспечивает взаимодействие интернет-магазина на базе WordPress + WooCommerce с платёжным сервисом [ХуткiГрош](https://hutkigrosh.by): выставление счетов в ЕРИП (АИС "Расчет"), оплата картой (WebPay), QR-код, автоматическое обновление статусов заказов после оплаты.

> Плагин удалён из каталога плагинов WordPress.org (сентябрь 2025), установка возможна только вручную из zip-архива (инструкция ниже). Поиск по слову "Hutkigrosh" в админке WordPress ничего не найдёт, скачивайте архив по ссылкам из раздела "Скачать".

## Требования

- WordPress 6.0 и выше (проверено до 6.9), [WooCommerce](https://woocommerce.com/) 9.0 и выше (проверено до 10.4.3)
- PHP 7.4 и выше, расширение [cURL](https://www.php.net/manual/ru/book.curl.php)

## Установка (одинакова для обеих версий)

1. Создайте резервную копию Вашего магазина и базы данных.
1. Скачайте архив нужной версии (см. раздел "Скачать").
1. В админке WordPress: **Плагины > Добавить новый > Загрузить плагин**, выберите архив и нажмите "Установить".
1. Активируйте плагин в меню **Плагины > Установленные**.
1. Перейдите к настройке: **WooCommerce > Настройки > Платежи**, включите способ оплаты.

## Настройка Hutkigrosh API v3

### Шаг 1. Получите API-токен

В бизнес-аккаунте ХуткiГрош откройте **Настройки > Интеграция ПУ** (раздел доступен ролям "Владелец ПУ" и "Администратор ПУ"). Используйте токен с доступом к информации о ПУ и созданию/редактированию счетов.

### Шаг 2. Подключите магазин

1. В настройках способа оплаты вставьте токен в поле **API Токен**.
1. Нажмите кнопку "Актуализировать", модуль загрузит из ХуткiГрош списки: **Услуга**, **Розничная торговая точка**, **Кассовое место**.
1. Выберите значения в списках и нажмите "Сохранить изменения".

### Шаг 3. Остальные параметры

**Основное:**
* **Название магазина**: произвольное название Вашего магазина.
* **Путь в дереве ЕРИП**: путь, по которому клиент будет искать выставленный счёт (например, `АИС "Расчет" (ЕРИП) > Интернет-магазины/сервисы >`).
* **Срок действия счета (дней)**: как долго счёт будет доступен в ЕРИП для оплаты.
* **Sandbox**: тестовый режим работы, счета выставляются в тестовую систему `api-sandbox.hgrosh.by` с токеном тестовой системы.
* **Debug mode**: отображение деталей ошибок.
* **Использовать номер заказа**: если включен, на платежный шлюз отправляется локальный номер заказа (orderNumber), иначе локальный идентификатор (orderId).

**Экран успешного заказа:**
* **Секция "Инструкция"**: пошаговая инструкция по оплате счёта в ЕРИП.
* **Секция QR-код**: оплата счёта по QR-коду через мобильное приложение банка.
* **Секция Webpay**: кнопка оплаты счёта картой (переход на WebPay).
* **Текст успешного выставления счета**: может содержать HTML, допустимы переменные `@order_id`, `@order_number`, `@order_total`, `@order_currency`, `@order_fullname`, `@order_phone`, `@order_address`.
* **CSS файл для итогового экрана**: путь к собственному CSS-файлу оформления.

**Статусы заказов** (выбор из существующих статусов WooCommerce, в скобках рекомендуемое значение):
* **Статус при выставлении счета**: какой статус установить заказу после выставления счёта в ЕРИП. Рекомендуется "На удержании" (`wc-on-hold`), заказ ожидает оплаты.
* **Статус при успешной оплате счета**: рекомендуется "Обработка" (`wc-processing`), оплата получена, заказ готов к выполнению.
* **Статус при отмене оплаты счета**: рекомендуется "Отменён" (`wc-cancelled`).
* **Статус при ошибке оплаты счета**: рекомендуется "Неудавшийся" (`wc-failed`).

**Уведомления** (отправляются шлюзом ХуткiГрош):
* **Email оповещение**: письмо клиенту при успешном выставлении счёта.
* **Sms оповещение**: SMS клиенту при успешном выставлении счёта.

**Способы оплаты для клиента:**
* **Название способа оплаты**: название, отображаемое клиенту при выборе способа оплаты (по умолчанию "Через систему 'Расчет' (ЕРИП)").
* **Описание способа оплаты**: описание, отображаемое клиенту при выборе способа оплаты.

### Обязательно: адрес обработчика уведомлений

Для автоматического обновления статуса заказа (после оплаты клиентом счёта в ЕРИП) сообщите в службу технической поддержки ХуткiГрош адрес обработчика, указав Ваш домен:

```
https://ваш-домен/?wc-api=gateway_hutkigrosh
```

Либо настройте адрес самостоятельно в личном кабинете сервиса: **Уведомления > Уведомления услуг**, выберите услугу и нажмите "Редактировать", в блоке "Оплачен/сторнирован" укажите URL обработчика и выберите версию v1 в селекторе рядом с полем. Модуль принимает уведомление GET-запросом с идентификатором счёта (`purchaseid`) в URL, формат v2 (POST) не поддерживается.

### Тестовый режим (Sandbox)

1. Получите API-токен тестовой системы (выдаётся при регистрации в ХуткiГрош).
1. Включите в настройках модуля режим Sandbox и введите токен тестовой системы.
1. Счета будут выставляться в тестовую систему `api-sandbox.hgrosh.by`.
1. Для эмуляции оплаты счёта используйте личный кабинет тестовой системы.

Документация API v3: https://api-dev.hgrosh.by/eripservice/docs/ru/index.html

## Одновременная работа и переход на API v3

* Плагины независимы: модуль API v3 ставится рядом со старым, заказы и данные магазина не затрагиваются.
* Адрес обработчика уведомлений у обеих версий общий (`/?wc-api=gateway_hutkigrosh`), при переходе сообщать в поддержку ничего не нужно.
* На время перехода включайте только один способ оплаты (либо старый, либо API v3), иначе уведомления будут обрабатываться дважды.

Рекомендуемый порядок перехода:

1. Установите модуль API v3 и настройте его по шагам выше.
1. Проверьте выставление и оплату счёта в режиме Sandbox.
1. Переключите способ оплаты на API v3, деактивируйте старый плагин.
1. Проверьте обработчик уведомлений (статус заказа в магазине должен обновляться).
